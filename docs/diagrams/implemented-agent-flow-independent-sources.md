# Implemented agent workflow: evidence map

This diagram models operationally documented behavior, not observed executions.
It is a historical snapshot from before `/commands/workflow` and the skill consolidation;
its path citations are not current instructions. Consult the live skill files.

- **E1 — Entry gap.** The complete workflow skill is for an explicitly requested workflow (`agent-home/skills/workflow/SKILL.md:2-13`). The declared command inventory does not include `workflow` (`bootstrap.sh:108-139`), so repository sources do not establish which mechanism loads `$workflow` from an ordinary user message.
- **E2 — Codex dispatch and registration.** `UserPromptSubmit` runs the command dispatcher (`codex/hooks.json:2-20`). It recognizes `/commands/<name>`, reads the wrapper, substitutes arguments, and injects the matching skill (`config/bin/codex-command-dispatch.mjs:7-8,37-64`). Bootstrap links commands and skills and installs the declared role TOMLs plus the dispatcher (`bootstrap.sh:69-73,379-395`). The standalone plan, review-plan, code, review, and cleanup wrappers map to their respective skills (`codex/commands/plan-implementation.md:1-8`; `codex/commands/review-plan.md:1-7`; `codex/commands/code.md:1-7`; `codex/commands/review.md:1-7`; `codex/commands/cleanup.md:1-7`).
- **E3 — Planning and authorization.** Workflow stages cover first draft, candidate improvement/acceptance, adversarial review, and slice preparation with human authorization for implementation, worktree, and live actions (`agent-home/skills/workflow/SKILL.md:41-61`). Planning requires explicit approval before its final plan is written (`agent-home/skills/implementation-planning/SKILL.md:89-105`).
- **E4 — Adversarial plan review.** `$review-plan` routes one fresh read-only `critic`; the main agent may rebut once, resolves findings or asks the user, then invokes `refine-plan` (`agent-home/skills/review-plan/SKILL.md:16-31,52-57`). The role is read-only and ends after one critique pass (`codex/agents/critic.toml:1-24`).
- **E5 — Implementation and correction loop.** Small plans route to one retained coder; large plans use a read-only supervisor with one coder (`agent-home/skills/workflow/references/coding-loop.md:6-15`; `agent-home/skills/code/SKILL.md:49-55`). Required review findings are verified; in-scope P0–P3 corrections return to coding, affected checks/reviews repeat, and two failed rounds escalate (`agent-home/skills/workflow/references/coding-loop.md:18-31`). Coder live validation remains pending approval (`codex/agents/coder.toml:13-20`); large-plan supervisor stays read-only and within its grant (`codex/agents/coding-supervisor.toml:8-28`).
- **E6 — Review branches and opt-ins.** Flash uses `reviewer-quick` (`agent-home/skills/review/references/presets/flash.md:1-9`); direct review uses `review-worker`, while swarm selects justified specialists (`agent-home/skills/review/SKILL.md:103-113`; `agent-home/skills/multi-agent-review/SKILL.md:33-55`). The review coordinator does not edit or invoke a fixer (`codex/agents/review-worker.toml:8-22`). Swarm-smart adds a verifier (`agent-home/skills/review/references/presets/swarm-smart.md:1-17`); full adds `live-validator` only after bounded authorization (`agent-home/skills/review/references/presets/full.md:1-12`). OCR and Slopo are separate explicit opt-ins (`agent-home/skills/workflow/SKILL.md:95-101`).
- **E7 — Checkpoint and cleanup feedback.** After coding gates pass, the workflow creates only the authorized local checkpoint and invokes a read-only findings audit; verified in-scope simplifications return through coding (`agent-home/skills/workflow/SKILL.md:70-72`; `agent-home/skills/workflow/references/cleanup.md:1-11`).
- **E8 — Human result gate.** Presentation includes observed behavior, checks, findings, artifacts, and evidence gaps; human corrections return through coding, while acceptance gates plan-named Git actions (`agent-home/skills/workflow/references/present-to-human.md:1-10`).
- **E9 — Shipping and dependent slices.** Run only Git actions named by the plan, inspect required CI/review, and start dependent slices from the accepted predecessor head after gates pass (`agent-home/skills/workflow/references/ship-pr.md:1-15`; `agent-home/skills/workflow/SKILL.md:75-89`).
- **E10 — Delegation owner and lifecycle.** `super-agent` owns delegation, role/model selection, nesting, permissions, and reporting (`agent-home/skills/super-agent/SKILL.md:8-12,27-39`). Launch, wait, resume, and release follow the active environment lifecycle when present (`agent-home/skills/super-agent/references/lifecycle.md:6-17`).

## Evidence gaps

1. No `/commands/workflow.md` wrapper is in the declared inventory; the ordinary user-message-to-`$workflow` loading mechanism is unspecified (`bootstrap.sh:108-139`).
2. Live validation requires the named environment, flow, sample, expected results, allowed side effects, stop bounds, and bounded authorization; otherwise it is blocked/unverified (`agent-home/skills/review/references/presets/full.md:3-12`; `codex/agents/live-validator.toml:8-25`).
3. Worker harness/model selection and lifecycle depend on the active wrapper and its capabilities (`agent-home/skills/super-agent/SKILL.md:27-39`).

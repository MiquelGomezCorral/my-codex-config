# Live test rules

Read this file before a live test and follow it. The rules bind the `computer-controller` agent in tester mode, when its task is a live test.

Load `code-quality` before judging code, and `test-audit` too when tests are in scope. Validate only the application flow named by an approved plan or later human approval. Before acting, confirm the test's `refine-plan` fields: `Flow`, `Samples`, `Where`, `Can run`, `Expected`, `Reset`, and `Bounds`. Together they give the target environment, exact flow, sample inputs, expected results, allowed side effects, and stop bounds. If any are missing or conflict, ask the workflow coordinator and do not start.

When the target is an LLM agent or chatbot, load `agent-tests-agent`, use its sections 2-7 only (intake comes from the fields above and the report from the `full` preset, with no page), and talk to it the way a real user would. Use the running instance the `$review` parent supplies, and leave its start, stop, and shared-data reset to that parent. Start an instance only when one is explicitly assigned to you: make one straightforward attempt, and if it does not start, stop and report `not possible: <reason>` with the evidence instead of working around the environment. Run each test as many times as the packet's run count says (the coding loop's live-test schedule sets it; with no count given, run a non-deterministic target 3 times). Between repeats, restore only your own test data and ask that parent to reset any shared data the test changed; never stop the shared app.

Use only tools already available in the current harness. Do not install or authenticate tools, except the pinned Playwright CLI install in your agent instructions. Do not deploy configuration, broaden the flow, edit product source, or perform Git actions. Keep workspace files read-only, and never edit the live test set or its samples. Do not use production credentials or data unless the human explicitly authorized that exact use. Stop if the flow exceeds its approved bounds.

Observe the interactions and resulting outputs, and inspect logs or telemetry only when available and authorized. Redact credentials and private data from the report. Separate observed results from inference; mark unavailable evidence blocked/unverified rather than calling it a defect or a pass. Report each test's result and evidence as the review skill's `full` preset defines them. After the run, stop and reset only an instance assigned to you.

Return the exact flow run, environment, sample, expected and observed results, each test's result, evidence references, side effects, cleanup status, and any gaps. Never claim success from static checks or a partial flow.
